# Phase VI - a second backbone, and whether the agent transfers

Branch `final-eval`. The H6 criteria were fixed in
`reports/final_eval_plan.md` section 6 (commit `b64ed9d`) **before any Swin
prediction was scored**.

## Summary

**H6 is supported. The agent transfers to a backbone it was not built on.**

Applied completely unchanged - the same Q model, the same `p_failure` detector,
the same thresholds and budget, all fitted on nnU-Net out-of-fold data - the
final agent improves SwinUNETR predictions on test:

| criterion (frozen in advance) | required | Swin result | met |
|---|---|---|---|
| dDice non-inferior | lower bound > -0.01 | **+0.0098 [+0.0041, +0.0169]** | yes |
| tumour-free FP count not increased | <= 78 | **72** (6 cleared, 0 added) | yes |
| lesion sensitivity non-inferior | >= -0.01 | **-0.0017** | yes |
| at least one co-primary improves | >= 1 | both | yes |

The same agent on the single nnU-Net fold-0 model meets all four as well, and by
a wider margin: dDice **+0.0149 [+0.0024, +0.0320]**, 60 -> 50 patients cleared.
So the honest reading is **"helps on both, less on Swin"**, which the
pre-registered design was built to distinguish from "helps on neither".

**But the backbone itself is a clear negative result.** SwinUNETR-small, MAE
pre-trained, is significantly worse than nnU-Net under matched conditions, and
the agent recovers only about a sixth of the gap.

## 1. The model

MONAI SwinUNETR built exactly as `petct/models.py: build_swin_unetr` with
`ARCHS["small"]` - `feature_size=24`, `depths=(2,2,2,2)`,
`num_heads=(3,6,12,24)`, `use_v2=True`, `downsample="mergingv2"` - inside
nnU-Net as `nnUNetTrainer_SwinSmall500`, on Dataset505, `nnUNetPlans_MAE`,
fold 0, the 738/76 split, 500 epochs. 18.3 M parameters.

Weight transfer from `swin_small_mae_best.pth` through `load_foundation_weights`:
**167 tensors loaded, 0 missing, 0 unexpected**. The loader fails loudly on a
prefix mismatch rather than silently training from random weights, and the clean
count is what confirms the foundation weights actually arrived.

Patch size **[192, 96, 128]**, divisible by 32 on every axis, asserted in the
trainer rather than assumed.

Training was stable on nnU-Net's default SGD at 1e-2 throughout - pseudo dice
0.18, 0.34, 0.51, 0.65, 0.72, **0.7687** - so the AdamW 1e-4 fallback built into
the trainer was never used. 500 epochs at 150-155 s, about 21 hours.

### Two things nnU-Net needed to host this architecture

**Deep supervision.** SwinUNETR returns a single tensor, not a resolution
pyramid, so deep supervision is off. nnU-Net's `set_deep_supervision_enabled`
then reaches for `self.network.decoder.deep_supervision`, which SwinUNETR does
not have. That raised `AttributeError: 'SwinUNETR' object has no attribute
'decoder'` **inside a dataloader worker**, and surfaced only as "One or more
background workers are no longer alive" with the real message several frames up.
Overridden as a no-op.

**MONAI** was not installed in the nnU-Net environment; it lives in the
standalone `petct` venv. Installed with `--no-deps` so nothing already there was
upgraded.

### Deviation

`build_swin_unetr` sets `use_checkpoint=True`. Gradient checkpointing was turned
off for this trainer: it is exact recomputation, so gradients and the trained
model are unchanged, but it costs 0.727 s/step against 0.599 s/step - 25.2 h
against 20.8 h for 500 epochs - and peak memory rises 11.6 -> 17.0 GB, inside a
32 GB card. Agreed with the user before launch and recorded in
`final_eval_plan.md` section 7.

### MAE pretraining exposure

Both backbones in this comparison were initialised from MAE pretraining by
**Liu et al. 2026 (arXiv 2605.21835)**, over roughly 5,000 scans, and **that
corpus included AutoPET** (`midterm/training_runs.md` l.18, l.61-62). That
applies to `swin_small_mae_best.pth` and equally to `nnunet_v2_mim_best.pth`,
which is M0's ancestor.

The exposure is **symmetric**, so the Swin-against-nnU-Net contrast below is not
biased by it: both sides saw the same images during self-supervised pretraining,
without labels. What it does mean is that **no model in this project was
pretrained on a corpus disjoint from the evaluation data**, so the absolute test
numbers anywhere in this project should not be described as performance on
wholly unseen data.

## 2. Experiment 1 - Swin against the single nnU-Net

The comparator is the **single nnU-Net fold-0 model**, not the 5-fold ensemble.
Phase IIIb priced the ensemble at +0.0213 Dice over a single model, so one Swin
against five nnU-Nets would measure the ensemble rather than the backbone. Both
sets of maps were generated by the same `cv_predict.py` with `--trainer` and
`--folds 0`, so they share preprocessing, logit-averaged 8-flip fusion and the
`u_stab` definition.

### Validation (n=76)

| metric | nnU-Net f0 | Swin | delta |
|---|---|---|---|
| Dice (tumour-positive) | 0.6959 | 0.6594 | **-0.0365 [-0.0611, -0.0140]** |
| FP volume mL | 10.142 | 15.778 | +5.636 [-0.245, +13.355] |
| FN volume mL | 4.282 | 4.583 | +0.301 [-2.215, +3.055] |
| HD95 | 79.73 | 130.06 | **+50.34 [+14.48, +99.31]** |
| lesion sensitivity | 0.5920 | 0.5505 | -0.0415 |
| tumour-free with any FP | 26/38 | 32/38 | +6 |

### Test (n=200)

| metric | nnU-Net f0 | Swin | delta |
|---|---|---|---|
| Dice (tumour-positive) | 0.6425 | 0.5860 | **-0.0565 [-0.0866, -0.0280]** |
| FP volume mL | 15.934 | 23.790 | **+7.856 [+1.139, +15.361]** |
| FN volume mL | 5.372 | 5.391 | +0.018 [-1.097, +1.098] |
| HD95 | 128.27 | 188.22 | **+59.95 [+29.28, +94.95]** |
| lesion sensitivity | 0.5517 | 0.5178 | -0.0339 |
| tumour-free with any FP | 60/90 | **78/90** | +18 |

**SwinUNETR-small is the weaker backbone, and not marginally.** The result
replicates on both splits with intervals excluding zero for Dice and HD95, and
on test for FP volume as well. It fails in the direction that matters
clinically: 78 of 90 tumour-free test patients carry at least one false
positive, against 60 for nnU-Net.

Note also that FN volume is essentially identical (+0.018 mL on test) while FP
volume is half again as large. Swin is not missing more tumour; it is drawing
more things that are not tumour.

The MAE pre-training does not rescue this. The transfer was clean - 167 of 167
tensors - so the comparison is of two properly initialised architectures, and on
this task and this data scale the convolutional one wins.

## 3. Experiments 6 and 7 - transfer, and H6

The final agent, **unchanged in every component**: fixed `topology_remove`,
`p_failure >= 0.90` from the nnU-Net-fitted detector, the Q gate using the
nnU-Net-fitted Q model, T = 10. Nothing was refitted, rescaled or re-thresholded
for Swin.

### Test (n=200, 110 tumour-positive, 90 tumour-free)

| | on Swin | on nnU-Net f0 |
|---|---|---|
| Dice | 0.5860 -> **0.5958**, +0.0098 [+0.0041, +0.0169] | 0.6425 -> **0.6574**, +0.0149 [+0.0024, +0.0320] |
| tumour-free with any FP | 78 -> **72** (6 cleared, 0 added, p=0.031) | 60 -> **50** (10 cleared, 0 added, p=0.0020) |
| FP volume mL | -3.193 [-5.945, -1.252] | -1.713 [-3.390, -0.520] |
| HD95 | -4.94 [-13.83, +0.58] | **-15.92 [-33.02, -3.93]** |
| lesion sensitivity | -0.0017 | -0.0028 |
| improved / unchanged / degraded | 12 / 97 / **1** | 9 / 100 / **1** |

### Validation (n=76)

| | on Swin | on nnU-Net f0 |
|---|---|---|
| Dice | +0.0042 [-0.0001, +0.0099] | +0.0004 [-0.0014, +0.0025] |
| tumour-free with any FP | 32 -> 31 | 26 -> 22 |
| lesion sensitivity | **+0.0000** | -0.0014 |
| improved / degraded | 3 / 1 | 1 / 1 |

### Verdict: H6 is SUPPORTED

All four pre-registered criteria are met on the Swin test predictions, and all
four are met on nnU-Net as well. The agent is not backbone-specific.

**The transfer is real but weaker.** +0.0098 against +0.0149 on Dice, 6 patients
cleared against 10. The pre-registered design asked for exactly this
distinction, and the answer is "helps on both, less on the backbone it was not
built on" rather than "helps on neither".

**The Q gate rejects far more on the unfamiliar backbone**, which is the most
informative number in this phase:

| | attempts | accepted | rejected by the Q gate |
|---|---|---|---|
| Swin, test | 460 | 90 | **80%** |
| nnU-Net f0, test | 177 | 58 | 67% |
| Swin, val | 157 | 23 | **85%** |
| nnU-Net f0, val | 52 | 13 | 75% |

Two things are happening at once. The detector proposes far more on Swin - 460
attempts against 177 - because Swin produces far more false positives for it to
find, which is the error distribution working as intended. And the Q model,
fitted on nnU-Net masks, is systematically less willing to approve edits to Swin
masks. Phase IV and the section 21 ablation both found the Q gate costs more
than it earns on nnU-Net; here it is costing more still. A sensible Phase VII
would ask whether the transfer gap closes once the gate is removed, since that
is the only component in the loop fitted to the shape of a particular model's
output rather than to anatomy.

**The agent does not rescue the backbone.** Swin with the agent reaches 0.5958;
nnU-Net without it is at 0.6425. The agent recovers about **17% of the 0.0565
backbone gap**. A better repair loop is not a substitute for a better base
model, which is the same lesson Phase IIIb taught when the 5-fold ensemble
(+0.0213) outperformed every refinement built on top of a single model.

## 4. What Phase VI establishes

1. **The agent is not backbone-specific** - every component was fitted on
   nnU-Net out-of-fold data and it still improves a transformer backbone's
   output on both co-primary endpoints, with one degraded case in 110.
2. **It helps less where it was not fitted**, and the Q gate is the prime
   suspect: it is the one component tuned to the shape of a particular model's
   masks, and its rejection rate rises from 67% to 80% on the unfamiliar
   backbone.
3. **SwinUNETR-small with MAE pre-training is a worse backbone than nnU-Net
   here**, by 0.057 Dice on test under matched conditions, driven by false
   positives rather than missed tumour.
4. **Repair does not substitute for a better base model.** 17% of the gap
   recovered.
